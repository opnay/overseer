# macOS 실행·셋업 검증

직접 실행은 메뉴바·launcher·Dock을 표시하고, 로그인 자동 실행의 `--background`는 메뉴바만 표시합니다. Homebrew·Docker CLI·Lima가 없거나 Engine이 없거나 복구가 필요하면 시작 준비를 표시합니다. 설정된 VM의 단순 중지 상태와 선택 도구인 Compose·QEMU의 미설치는 최초 셋업 사유가 아닙니다.

## 상태와 책임

- `app.rs`가 직접 실행·로그인 실행·닫기·종료를 조정합니다. 직접 실행의 범위에는 개발자가 새로 설치한 앱도 포함합니다.
- `/startup`이 필수 도구 설치 상태를 판단합니다. 화면은 대시보드 조회 실패와 무관하게 이 응답으로 도구 셋업에 진입합니다.
- `/menu-bar`는 필수 도구가 없으면 런타임을 조회하지 않고 `setupRequired: true`를 반환합니다. 도구가 있으면 VM의 미생성·복구 필요와 단순 중지를 구분합니다.
- 메뉴는 셋업 필요·최초 확인 중·조회 실패 때 **Overseer 열기**, **Overseer 종료**만 제공합니다. 확인된 정상 상태에서만 VM·Compose 메뉴를 제공합니다. 상태는 10초마다 다시 조회합니다.
- Homebrew 설치는 관리자 인증을 받는 공식 명령을 Terminal에서 직접 실행하도록 안내합니다. 앱이 관리자 암호를 수집하거나 무인 설치하지 않습니다.
- 로그인 등록 실패는 진단을 기록하되 앱·메뉴바·셋업 진입을 중단하지 않습니다. 로그인 등록은 기존 LaunchAgent 방식이며 앱 내부에 새 옵션 UI를 추가하지 않습니다.

## 설치본 수동 검증 케이스

아래는 자동 테스트 결과로 대체하지 않습니다. 이 PR에서 새 설치 Mac·실제 재부팅·강제 종료를 완료했다고 간주하지 않습니다.

- [ ] M01: 앱 완전 종료 후 Finder에서 실행 → 메뉴바·창·Dock 표시. 새 macOS와 개발자 신규 설치에서 동일합니다.
- [ ] M02: Homebrew도 없는 Mac → 시작 준비의 공식 명령으로 Terminal 설치 후 앱에서 재확인합니다. 메뉴는 두 항목만 표시합니다.
- [ ] M03: 도구만 준비된 Mac → Engine 생성 전에는 시작 준비·두 메뉴, 생성 완료 후에는 상태에 맞는 운영 메뉴로 전환합니다.
- [ ] M04: 설정된 VM을 중지하고 재부팅 → 로그인 자동 실행은 창 없이 메뉴바만 표시하며 VM을 시작하지 않습니다. 메뉴의 VM 시작을 누른 뒤에만 시작합니다.
- [ ] M05: 윈도우 닫기·Cmd+Q·Dock의 종료 요청 → 창만 숨기고 메뉴바·sidecar를 유지합니다. 재실행은 같은 프로세스의 창을 엽니다.
- [ ] M06: 메뉴의 Overseer 종료 → 앱·sidecar·소켓 정리. 실행 중인 VM·컨테이너 자체를 자동 중지하지 않습니다.
- [ ] M07: 활성 상태 보기에서 강제 종료 → UI는 종료되고 sidecar는 부모 stdin 종료에 따라 끝납니다. 다음 실행은 남은 소켓을 복구합니다.
- [ ] M08: 도구 제거·상태 조회 실패 → 다음 메뉴 갱신 때 운영 메뉴를 숨깁니다. 복구 후 다시 운영 메뉴로 전환합니다.
- [ ] M09: 로그인 자동 실행 권한·등록 실패 → 앱의 직접 실행과 셋업 화면은 계속 사용 가능합니다.
- [ ] M10: 앱 교체·업데이트 후 재실행, 중복 실행, 로그인 시점의 동시 실행 → 프로세스 하나와 메뉴바 아이콘 하나만 유지합니다.

## PR 경계

PR #1은 위 실행·셋업 표시·메뉴 정책을 소유합니다. PR #2는 Bun의 누락 실행 파일 오류에서 `ENOENT` 코드를 보존·판별하는 서버 회귀를 소유합니다. PR #1에 PR #2의 코드를 복제하지 않습니다. 내부 sidecar 자체가 시작되지 않는 손상·서명 문제는 필수 외부 도구 미설치와 구분하며 현재 앱 시작 실패로 처리합니다.
