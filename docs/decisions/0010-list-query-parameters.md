# 0010. 목록 API의 필터·정렬 쿼리 규약

## 상태

채택. 이미지 저장소 태그 조회 API부터 적용합니다. 기존의 다른 목록 API는 이번 변경에 포함하지 않습니다.

## 결정

목록 API는 필드 이름을 포함한 쿼리 파라미터를 사용합니다. 이는 프로젝트 규약이며, REST 자체가 특정 쿼리 문법을 강제한다는 의미는 아닙니다.

- `sort=필드`: 오름차순, `sort=-필드`: 내림차순입니다. 허용 필드와 기본값은 API별로 정합니다.
- `filter[필드]=값`: 해당 필드의 필터입니다. 일치 방식과 길이 제한은 API별로 정합니다.
- 필터 적용 후 정렬하고 마지막에 페이지를 나눕니다. 응답 `count`는 필터를 통과한 전체 항목 수입니다.
- 지원하지 않는 정렬 값·필터 필드와 제한을 넘는 필터는 `400`으로 거부합니다. 복수 정렬과 필터 연산자 문법은 현재 제공하지 않습니다.
- 필터나 정렬을 변경하면 클라이언트는 1페이지부터 조회합니다.

## 이미지 저장소 태그 조회

`GET /api/image-repositories/:id/tags`

| 파라미터         | 값·기본값                                    | 동작                                                                                                                                                                                         |
| ---------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `page`           | 기본 `1`, 범위 `1..10000`                    | 페이지당 25개를 반환합니다.                                                                                                                                                                  |
| `sort`           | `tag`, `-tag`, `lastUpdated`, `-lastUpdated` | 태그 이름 또는 갱신일 오름·내림차순입니다. Docker Hub 일반 목록은 기본 `-lastUpdated`, 다른 registry·기존 필터 조회는 `tag`입니다. 날짜 정렬은 Docker Hub의 필터 없는 목록에서만 지원합니다. |
| `filter[tag]`    | 선택, 앞뒤 공백 제거 후 최대 128자           | 태그 이름의 대소문자를 구분하지 않는 부분 일치입니다. 비어 있으면 필터를 적용하지 않습니다.                                                                                                  |
| `filter[digest]` | 선택, 최대 256자                             | manifest digest의 대소문자를 구분하지 않는 부분 일치입니다.                                                                                                                                  |
| `filter[search]` | 선택, 최대 256자                             | 태그 이름 또는 manifest digest에 부분 일치하면 포함합니다.                                                                                                                                   |

필터 값은 앞뒤 공백을 제거하며 비어 있으면 적용하지 않습니다. 서로 다른 필터를 함께 지정하면 AND로 결합합니다. `filter[search]` 안에서는 이름과 digest를 OR로 비교합니다.

태그 정렬은 즐겨찾기 그룹과 일반 그룹 안에서 각각 적용합니다. 즐겨찾기는 정렬 방향과 관계없이 앞에 배치합니다. 첫 페이지의 남는 자리는 일반 태그로 채우고, 즐겨찾기가 25개를 넘으면 다음 페이지에도 이어서 표시합니다. 검색에 일치하지 않거나 원격에서 사라진 즐겨찾기는 결과에 포함하지 않습니다.

예: `GET /api/image-repositories/:id/tags?page=1&sort=-tag&filter[tag]=alpine`

실제 URL의 대괄호와 검색어는 `URLSearchParams` 등으로 인코딩합니다. 응답의 `count`는 필터 결과 수, `totalCount`는 전체 태그 수입니다. 화면은 검색 입력 없이 `page`와 `sort`만 전달합니다.

Docker Hub의 일반 목록은 Hub API의 `ordering`과 페이지 조회를 사용합니다. `tag`는 `-name`, `-tag`는 `name`, `lastUpdated`는 `-last_updated`, `-lastUpdated`는 `last_updated`에 매핑합니다. 이 매핑은 공개 API 실측을 근거로 하며 `ordering`은 현재 Hub 공식 OpenAPI에는 없는 파라미터입니다. 일반 목록에서 전체 태그 메타데이터나 전체 해시 인덱스를 미리 수집하지 않습니다.

각 정렬의 원격 페이지를 100개 단위로 필요할 때부터 읽고 캐시합니다. 즐겨찾기는 원격 단일 태그 조회로 보완한 뒤 정렬하여 앞에 배치하고, 일반 태그 스트림에서는 제외합니다. 이 때문에 처음부터 먼 페이지로 이동하면 즐겨찾기 제외 위치를 맞추기 위해 앞선 페이지를 추가 조회할 수 있습니다. 캐시는 마지막 사용 후 60초에 만료하고 수동 동기화·저장소 삭제 시 교체·삭제합니다. 삭제된 즐겨찾기는 행에 포함하지 않습니다. 동기화의 태그 수는 Hub 첫 응답의 전체 count를 사용합니다.

Hub의 익명 접근은 깊은 페이지를 403으로 제한할 수 있습니다. 이 경우 목록을 빈 결과나 이름순으로 바꾸지 않고 인증이 필요한 조회 제한 오류를 표시합니다. 인증 기능은 이번 범위에 포함하지 않습니다. 데이터가 조회 도중 변경될 때 원격 페이지의 스냅샷 일관성은 보장되지 않습니다.

기존 필터 API는 Registry V2 이름 캐시 기반으로 유지합니다. 날짜 정렬과 필터의 결합은 400으로 거부합니다. 이 경로는 이름 캐시에서 필터·즐겨찾기 우선·정렬·페이지 분할을 적용하고 프런트에는 25개만 반환합니다.

## 클라이언트

태그 화면에는 검색 입력을 제공하지 않습니다. `태그` 헤더는 이름 오름·내림차순, `갱신일` 헤더는 날짜 오름·내림차순을 전환하고 정렬·즐겨찾기 변경 시 1페이지부터 표시합니다. Docker Hub는 갱신일 최신순이 기본이며, 다른 registry는 이름순이 기본이고 날짜 정렬 버튼은 비활성화합니다.

태그 이름 아래에는 해시 대신 `linux/amd64`, `linux/arm64/v8` 같은 OS/아키텍처/variant 배지를 나열합니다. 동일 플랫폼은 한 번만 표시하며 `unknown/unknown`은 플랫폼 정보로 표시하지 않습니다. 플랫폼을 제공하지 않으면 `플랫폼 정보 없음`, 날짜를 제공하지 않으면 `—`를 표시합니다. Docker Hub의 날짜는 태그 `last_updated`이며 OCI config의 빌드 날짜로 대신하지 않습니다.

응답 태그에 선택 필드 `lastUpdated`, `platforms`를 추가합니다. `digest`는 API에서 유지하되 목록 UI에서는 노출하지 않습니다. 다운로드와 컨테이너 생성에는 기존 `저장소:태그` 참조를 계속 사용합니다.

저장소 목록의 `official`은 Docker Hub의 `library` namespace에만 적용합니다. 임의로 추가한 주소의 실재 여부를 인증한 필드는 아니며 namespace 분류입니다. 다른 registry의 `library`나 서명 여부에는 확대하지 않습니다. 저장소 등록·목록·상세에서 동일한 분류를 반환하며 별도 DB 마이그레이션은 하지 않습니다.

## 원격 조회와 해시 검색 준비

- Docker Hub를 포함한 registry의 태그 이름은 Registry V2 `tags/list?n=1000`과 `Link` 페이지를 사용해 조회합니다. 서버가 더 작은 페이지를 반환하면 그 `Link`를 따릅니다. 최대 100페이지를 허용합니다. Docker Hub의 익명 메타데이터 API는 깊은 페이지를 403으로 거부하므로 전체 목록 수집에 사용하지 않습니다.
- 다른 registry 목록과 기존 이름 필터에서는 선택한 페이지의 태그만 manifest GET으로 보완합니다. OCI index의 descriptors.platform을 사용하며 단일 manifest는 config blob의 OS/아키텍처를 조회합니다. 이름 검색어가 유효한 SHA-256/SHA-512 digest에 포함될 수 없으면 전체 해시 조회를 시작하지 않습니다.
- 해시 필터나 해시일 수 있는 검색어는 전체 digest 인덱스를 준비합니다. 아직 준비 중이면 HTTP `202`와 `digestIndex: { completed, total }`을 반환합니다. 이때 `count=0`과 빈 tags는 미완료 자리표시자이며 빈 검색 결과가 아닙니다. 이 서버 계약은 현재 UI에서 사용하지 않으며 UI가 polling을 시작하지 않습니다.
- 준비가 끝나면 HTTP `200`으로 필터·정렬·페이지 결과를 반환합니다. 최대 8개 manifest 요청을 병행하고 성공·미제공 결과를 캐시합니다. 원격에서 digest를 제공하지 않으면 임의로 생성하지 않습니다. 대규모 저장소의 최초 전체 해시 검색은 시간이 걸릴 수 있습니다.
- manifest GET은 OCI index/image와 Docker manifest list/v2를 수락하며 `Docker-Content-Digest`의 SHA-256/SHA-512 값을 사용합니다. 익명 bearer token이 만료되어 401이 오면 한 번 갱신해 재요청합니다.
- 원격 HTTP 오류는 검색 결과 0건으로 바꾸지 않고 오류로 전달합니다. 실패한 digest 요청은 재시도할 수 있으며, 저장소 삭제·수동 동기화·캐시 교체 시 기존 인덱스 작업은 다음 요청 묶음부터 중단합니다.

근거: [Docker Registry V2 목록·manifest 규약](https://distribution.github.io/distribution/spec/api/), [OCI Distribution 명세](https://github.com/opencontainers/distribution-spec/blob/main/spec.md). Docker Hub 공개 node에서 이름 9천여 개와 첫 페이지 digest, 이름 검색·정렬·즐겨찾기를 실제 검증합니다. Hub 메타데이터 API의 익명 1천개 초과 페이지 403을 수정 전 실패 회귀로 보존합니다.
